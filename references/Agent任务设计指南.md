# Agent 任务设计指南

## 适用范围

Agent 任务指 General Agent 场景。核心目标是直接完成真实的业务、办公、研究、数据处理、内容制作、辅助决策或生活服务工作。

任务类型按主要目标和核心交付物判断，不按使用工具判断。使用 Python、SQL、浏览器、Excel、网页或脚本，不会自动把任务变成 Coding。

## 默认规模

当期任务书没有另行规定时，按以下默认值设计：

1、每批次 3 个 Agent 任务。

2、每个任务内部目标为每个模型实际工具调用不少于 100 次。

3、最终提示词不得出现工具调用次数，也不得要求模型凑调用。

4、通过真实任务复杂度、资料核验、专业判断、交付物和验收标准自然形成多步骤执行。

当期任务书的任务数量、调用门槛和平台限制高于本指南时，以任务书为准。

## 任务有效性门槛

设计任务前先读取 `references/众测专家快速上手指南.md`，确认以下条件：

1、任务来自近期真实工作，结果会被用于决策、交付、复盘或推进项目。

2、任务需要专业判断，不能只靠摘抄、改写、套模板或执行固定步骤完成。

3、必要材料可以直接提供、脱敏还原或通过合规公开渠道获取。

4、模型需要自主选择方法、工具或下一步行动，提示词没有泄露结论和完整答案路径。

5、交付物、使用者、用途和完成标准明确，用户可以判断结果能不能用。

任一核心条件不满足时，先补任务背景或换题，不用附加无关步骤弥补复杂度。

## 设计流程

1、确认真实背景、实际使用者和最终用途。

2、列出模型可获得的材料、允许使用的公开来源和工具条件。

3、明确模型必须完成的专业判断，以及最容易出错的业务约束。

4、确定一个便于验收的主要交付物。可使用 HTML、PPT、Excel、Word、调研报告或其他办公文件。

5、设计一个完整首轮提示词，写清背景、目标、材料、业务约束、交付要求和完成标准。

6、保留模型自主选择方法和行动顺序的空间，不提供关键结论、优先级答案或完整分析过程。

7、在提示词文件底部保留一个按需发送的备用提示词，扩大真实资料范围或补充核验，不重复首轮内容。

8、生成 5–8 分钟内可以完成的手动验收清单，优先检查关键事实、来源和最终可用性。

## 提示词结构

Agent 任务提示词包含以下内容即可，不强制照搬固定标题：

1、任务背景和实际用途。

2、任务目标。

3、可用材料和公开来源范围。

4、必须遵守的业务约束和例外。

5、主要交付物及格式。

6、完成标准和关键验收点。

7、单独分隔的备用提示词，注明只有收到该段后才实施。

## 自动化与人工验收

Agent 任务不强制启动服务。根据产物类型选择验证方式：

1、HTML 检查可打开性、结构、链接、来源和关键交互。

2、PPT 检查文件可编辑性、页数、文字溢出、素材显示和事实准确性。

3、Excel 检查公式、联动、数据类型、边界输入和汇总结果。

4、Word 或调研报告检查结构、来源、关键事实、引用和可读性。

5、涉及外部数据时抽样交叉核验高风险结论，不要求用户复查所有来源。

6、自动化测试完成后，只把最值得确认的 3–6 个问题交给用户手动验收。

## 评测输出

Agent 与 Coding 共用统一的 1–10 分报告主体：

1、产物质量。

2、执行过程。

3、执行过程圈选评论。

4、产出物反馈。

Agent 的圈选证据可以来自执行轨迹、文件章节、页面位置、PPT 页码、表格单元格、来源链接或其他可复核位置，不强制提供代码行号。
