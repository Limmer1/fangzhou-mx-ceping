# 评价文字整理规则（所有类型共用）


适用于 Coding、Agent、高质量 Rubric 激励专项及后续测评类型。凡是测评者自行撰写或修改的评价，都必须执行本规则；原始证据和用户明确要求原样保留的内容不改写。

1、生成或修改评价前，优先调用 `wenzi-zhengli` Skill，按其完整流程整理文字和去 AI 味。

2、当前环境没有该 Skill 时，主动从可用 Skill 或 Skill 搜索能力中寻找“文字整理、润色、去 AI 味”类 Skill，读取说明后调用。不要跳过，也不要等用户提醒。确实找不到时，直接按本节规则整理。

3、评价使用用户本人准备提交的口吻。体验和判断用第一人称；事实可以直接写。语言口语化、具体、短句，不写第三人称代评。

4、每个编号评价小点只说一个判断，正文以 40–50 个汉字为目标，最多 50 个汉字。序号、归因标签、文件路径和代码块不计入。超过时拆成两个小点，不能删掉关键事实凑字数；纯数据项、检查项和原始证据不强行凑字数。

5、比较多个模型时，统一写“4个模型”“3个模型”或“这些模型”，不用“四家”“三家”“几家”等机构化称呼。

6、测评者自行撰写的评价正文不使用中文冒号 `：` 或英文冒号 `:`，改成完整句或自然分句。文件路径行号、URL、代码、原始引用、截图文件名和平台原始字段保持原样。

7、测评者自行撰写的评价禁用：`不是……而是……`、`并不是……而是……`、`不但……而且……`、`不仅……还……`，以及用“还是”作转折或填充。改成直接陈述。

8、任务涉及模型文件夹或模型顺序时，收到平台模型截图后，按截图从上到下给模型文件夹加序号，格式为 `1、visor`、`2、wicket`。每个任务都使用同一组序号；有状态时写成 `1、visor【已发完】`。评分表的模型行、逐模型章节、执行数据表、平台短评和批次汇总表都按文件夹序号排列，不按字母、得分或效率重排；排名字段和综合排名仍写真实名次。截图缺失或看不清时先问用户，不能猜。

9、报告写完后必须再次调用同一个文字整理 Skill 复扫，并检查冒号、禁用句式和 40–50 字目标；任务涉及模型称呼或模型顺序时，再检查相应内容。未通过不得交付。

10、本规则适用于测评者自行撰写的评价，包括评分汇总、各维度评分依据、执行过程圈选说明、平台短评、模型对比，以及 Rubric 校准的判断依据、修改后的表述和新增评分标准。`产出物反馈`、代码片段、原始题目、原始判据、原始引用、平台数据、截图文件名及用户要求逐字保留的文字属于证据或已确认内容，保持原文，不做语言整理。


不涉及多个模型时，不强行比较或生成排名；不涉及模型文件夹和顺序时，跳过相应规则。Rubric 的修改后表述和新增判据仍需进行文字整理，应保留完整的评分档位、数字、公式和边界；字段名、平台选项和评分档位中的必要冒号按原格式保留。
