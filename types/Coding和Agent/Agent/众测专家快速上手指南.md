只有有效的测评才能满额结算。一次测评有没有效，就看两件事：高质量的真实任务 + 你自己的真实评价。

| **两个关键点** | **做到什么算过线** | **这些不算** |
|-|-|-|
| 高质量的真实任务 | 你真正做过、结果会被实际使用的复杂项目，需要专业判断才能完成。 | 临时编的知识问答；为难住模型而故意绕弯、堆无关限制的怪题。 |
| 真实的评价 | 模型答完后，你用自己的专业判断说清哪里对、哪里不行、能不能用。 | 套话、凑数；只打分不说理由。 |

这份文档教你把工作里的复杂项目，改写成一道能测出模型水平的评测题。第一次出题的新手专家必看，一次过线比反复返工省时间。

## 一、先选一件值得测试的真实工作

**先挑工作，再写题。**

这是近期真实发生过的工作，来自真实项目、业务问题、客户需求或交付任务。

- 结果真的会被使用，会影响后续决策、项目推进、交付质量、效率、成本或风险。
- 过程中需要专业判断，不能只靠摘抄、改写、套模板或执行固定步骤完成。
- 必要材料可以提供，或者可以脱敏还原，模型拿到后能直接开始。

四项基本满足，这项工作才值得继续转化。

| **类型** | **Bad case** | **Good case** |
|-|-|-|
| Agent任务 | 金融任务：分析一下某只股票。 | 帮我搭一个Excel测算底稿，估一下长鑫和长存两大存储厂扩产能给国内半导体前道设备厂商各家带来多少受益。框架你自己设计一下，必须把每家的“新增月产能(万片/月)”做成可调假设格（改一格全表联动）。大致是按设备环节（刻蚀、薄膜、清洗、量测等）拆单线设备投资额，再用各环节国产厂商的市占率分摊到具体公司，落到每家的潜在订单/收入增量。最后，以一组现实的扩产假设为例(如长鑫、长存各新增约3万片/月)实测一版，给出各家设备厂商的潜在订单/收入增量结果。 |
| 电商任务 | 随便想一个营销活动。 | 作为专业的亚马逊选品分析助手，基于卖家精灵等合规API的真实返回数据，针对美国站点情人节相关非带电品类，严格遵循选品规则逐层筛选，最终找到10个符合预设合格标准的全新候选产品，生成可视化HTML选品报告，所有环节不跳过API校验流程，确保输出结果数据真实、符合蓝海准入要求、风险可控，为跨境电商用户的资源投入提供可靠决策依据。 |
| 销售任务 | 整理一套分渠道引流话术。 | 作为财务AI课程的销售老师辅助人员，基于用户提供的课程信息、业务相关资料以及十大AI应用小工具的引流获客背景，重新梳理面向引流客户的开场白话术，通过话术初步了解客户需求与痛点，引导客户体验AI小工具，为后续推荐整套财务AI课程做铺垫。 |
| Coding任务 | coding 任务：做一个练手网页。 | 开发 video-brand 与 object-storage 两个独立 Skill。准备 20 个视频，为每个视频添加图片 Logo、唯一文字水印和统一片尾；校验画面、时长及文件可播放后，上传腾讯云 COS，核对对象信息，刷新 CDN、查询任务状态，并从 CDN 下载文件比对一致性。验收以 20 个视频全链路真实跑通为准，需提交可复用的 Skill、执行日志、异常记录及校验结果。 |

> 💡 **过线标准：**这件事如果做完以后，没有人真的拿去决策、交付、复盘或推进工作，这题先别出。

## 二、从真实工作里提取模型需要承担的任务

**把工作还原出来，不要只给一句需求。**

**你至少补齐 5 个要素：**

1. 当时为什么要做这件事：背景、问题、目标。
2. 模型可以获得哪些材料：数据、文件、代码、业务资料、工具条件。
3. 模型需要完成什么专业判断：依据哪些信息判断什么。
4. 必须遵守哪些真实约束：规则、范围、例外，不要堆叠现实里不存在的限制。
5. 最终需要交付什么：交付物、使用者、用途。

你要做的动作：把自己当时做这件事的任务书补出来，补到模型拿到就能开工。

| **类型** | **不好的写法** | **改好后的写法** |
|-|-|-|
| Coding | 修一下支付问题。 | 排查并修复支付成功后订单状态未同步的问题。可使用订单表、支付回调日志、补偿任务日志和相关代码仓；需要遵守现有账务一致性规则；最终交付修复代码、根因说明和回归测试。 |
| Agent | 帮我做个增长分析。 | 请基于近两个月线索数据、投放数据、销售跟进记录和访谈纪要，判断新增下滑主要发生在哪个环节，并输出问题判断、原因拆解和优先动作建议，供季度经营会讨论。 |

> 💡 **先补事实，再补要求：**背景、材料、约束、交付这几项没写全，模型失败不一定是能力问题，可能只是题目没给够信息。

## 三、拿掉你的答案，留下模型的任务

**这一步最关键。**

**保留这些：**

- 真实背景
- 任务目标
- 必要材料
- 业务约束
- 交付要求
- 真实工作中必须执行的流程和验证动作

**不要提供这些：**

- 关键结论或判断结果
- 你自己的完整分析过程
- 可以直接照着执行的答案路径
- 哪个方案一定正确
- 各项因素的优先级答案

| **任务类型** | **不好的写法** | **改好后的写法** |
|-|-|-|
| Agent（以金融类任务为例） | 先看财报利润率，再重点看现金流，最后大概率结论是短期别加仓。 | 基于财报、电话会纪要、股价表现和行业信息，判断公司当前经营风险和后续策略建议；最终输出核心判断、风险点和建议动作，不直接提供现成结论。 |
| Coding | 先查回调表，再看幂等锁，八成是补偿任务挂了，你按这个思路修。 | 排查退款成功后账单状态未回写的问题。可使用订单表、退款回调日志、补偿任务日志和代码仓；需要遵守现有账务规则；最终交付修复代码、根因说明和回归测试。 |

> 💡 **别替模型做题：**你把自己的判断过程、方法顺序、正确答案塞进去以后，测到的就不是模型能力，而是模型复述你的能力。

## 四、把模型必须自主完成的考点钉清楚

高质量评测任务，不只是“有真实需求”，还要能有效考到模型能力。

**你直接回答这 3 个问题：**

1. 模型需要依据哪些信息，判断什么问题？
2. 模型需要自主选择哪些方法、工具或下一步行动？
3. 模型最容易在哪个业务判断或约束上出错？你将依据什么判断它做得对不对？

这 3 个问题写清楚了，模型考点才算立住。

| **类型** | **不好的写法** | **改好后的写法** |
|-|-|-|
| 个股深度研究 | 分析这家公司值不值得买。 | 模型需要依据财报、电话会纪要、行业数据和近期市场表现，判断经营变化、核心风险和后续策略；需要自己决定先看业务、财务还是市场信号，并识别哪些波动只是表象；结果用“判断是否抓住关键风险、结论是否有证据支撑、建议是否可执行”来验收。 |
| urllib3 录制回放 | 把这个库改一下。 | 模型需要根据现有代码结构、测试框架和录制回放需求，判断改造点应该落在哪些模块、如何保证兼容性、测试应补到什么程度；需要自己选择实现路径；结果用“功能是否可用、原有行为是否被破坏、测试是否覆盖关键分支”来验收。 |
| 重大故障应急指挥 | 给我一个故障处理方案。 | 模型需要依据监控告警、日志、故障时间线、系统架构和业务优先级，判断先止血还是先定位、应调度哪些角色、后续动作怎么排；需要自己决定行动顺序；结果用“是否优先处理高风险问题、是否符合应急约束、指令是否可执行”来验收。 |

> 💡 **有效模型考点：**难度来自真实任务本身，来自判断和取舍，不来自故意加很多无关步骤、无关限制或绕弯子设题。

## 五、把任务写成模型可以直接执行的 Prompt

Prompt 够用就行，不要为了显得专业写很长。一个高质量的Prompt包含但不限于以下要素，你在提交前可以对照以下角度进行自查以下要素是否齐全，无需照搬格式：

- 任务背景
- 任务目标
- 可用材料
- 业务约束
- 交付要求
- 完成标准

| **类型** | **不好的写法** | **改好后的写法** |
|-|-|-|
| Coding | 修一下订单状态问题，尽快。 | 排查并修复支付成功后订单状态未同步的问题。可使用订单表、支付回调日志、补偿任务日志和相关代码仓；需要遵守现有账务一致性规则，不能通过人工改库规避问题；最终交付修复代码、根因说明和回归测试。完成标准：支付成功场景下订单状态能在规定时间内正确更新，异常分支有明确处理。 |
| Agent | 帮我做个行业研究。 | 请基于行业数据、公司公开资料、竞争格局信息和近期市场变化，判断该赛道是否存在明确增长机会，并输出研究结论、核心依据和建议动作。不要直接复述资料，要形成自己的判断。完成标准：结论可用于决策讨论，关键判断有证据支撑。 |

> 💡 **判断 Prompt 是否过线：**目标清楚、信息够用、约束真实、没有泄露答案路径、结果可以验收。满足这5条，就可以进评测。

## 六、提交前最后自查

- [ ] 任务真实、有用，不是临时编题。
- [ ] 必要背景和材料已经给全，模型可以直接开始。
- [ ] 模型仍然需要自己判断，不是机械套模板。
- [ ] 交付结果明确，专家可以判断对不对、好不好、能不能用。

> 💡 **最后一句：**先找到真实工作，再拿掉你的答案，再把模型必须完成的判断点写清楚。这样出来的题，才真的能测到模型能力。
